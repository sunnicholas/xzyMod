1. 文件存储路径体系

所有文件存储由 com.xzy.common.config.XiziYiConfig 统一管理，根路径由 xzy.profile 配置：

环境配置文件profile 值
macOS 本地开发application-local.yml（已 .gitignore）/Users/sunnicholas/uploadPath
Ubuntu 服务器application-dev.yml/home/lims/uploadPath

XiziYiConfig 按业务类型生成 16 个子目录（见 module-architecture 文档）。此外，部分业务 Service 在代码中自定义了更深层的路径：

业务文件存储路径（相对于 profile）定义位置
委托单 Word/PDF/entrust/{entrustId}/委托单.docxMsEntrustTaskServiceImpl
证书 Word/PDF/cert/{entrustId}/{allotId}/证书.docxTestTaskAllotController
记录 Excel/record/{entrustId}/{allotId}/原始记录.xlsxPageOffice 保存回调
注意：entrust/、cert/、record/ 目录名是在 Service 代码中硬编码的，不是 XiziYiConfig 生成。
如需新增业务文件类型，优先使用 XiziYiConfig 已有的子目录，而非自定义新目录。

⚠️ PageOffice 常见坑：
• JDK 兼容：PageOffice 在 JDK 8 较稳定，JDK 17 需确认已安装对应版本（当前项目已适配）
• Linux 需安装 libstdc++: apt install libstdc++6
• 前端 PageOffice 组件 不能跨域，需同源访问
• 文件路径需要完整的绝对路径，posyspath 配置必须正确

⚠️ Aspose 水印问题：
如果生成的文件出现评估水印，检查 license.xml：

5. 文件下载与访问

/profile/** 为虚拟路径，由 ResourcesConfig 映射到 file:{profile}/：

// 前端访问 this.$download.name(fileName) // 指定文件名下载 this.$download.resource(url) // 下载服务器资源 this.$download.zip(url) // 下载 zip 包 // 后端下载端点 GET /common/download?fileName={filename}&delete={true|false}

6. 常见文件操作问题排查

现象原因排查步骤
Aspose 文件有水印license.xml 不正确或过期检查 resources/license.xml 是否存在；查看启动日志中的 license 加载信息
PageOffice 无法打开模板路径不对 / JDK 不兼容检查数据库 template_path 字段指向的文件是否存在；检查 JDK 版本和 PageOffice 版本匹配
上传文件找不到profile 配置不对或磁盘不足确认 xzy.profile 指向的路径有读写权限和空间；确认数据库存储的是相对路径 /profile/...
图片不显示路径不对或权限不足检查 Linux 文件权限：chmod -R 755 {profile}；检查 /profile/ 映射是否正确
Word 书签找不到模板中未插入对应书签用 Word 打开模板，检查书签名称是否与代码中 deviceTag 一致
🚫 禁区：
• 不要修改 ResourcesConfig 中的 /profile/** 映射（改后所有文件 URL 会 404）
• 不要在业务代码中写死路径分隔符，使用 File.separator 或 Path.of()
• 不要在生产环境修改或删除 license.xml
